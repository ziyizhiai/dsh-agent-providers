# 交互与稳定性升级说明

## 本轮范围

基于原仓库 main 的 d48493d 工作副本进行修改，不推送 GitHub，不修改用户现有 DSH、Agent 登录或全局配置。运行时仍支持 ACP SDK 1.4.0，保持外部 Agent 自己执行工具的边界。新增交互放在已有 conversation.composer.dock，不假设宿主存在未验证的聊天卡片接口。

## 已落实的问题与优化

### 会话连续性

- 恢复失败后，基于实际恢复结果改为完整重放，不再把增量发送给空白新会话。
- 保存完整对话消息游标、SHA-256 摘要和系统指令摘要。跨 Agent A→B→A、assistant 内容编辑、压缩、历史改写和系统变化均能触发重放。
- 尊重 continuity: replay；CLI 请求模型变化不续接旧会话。
- 老绑定采用保守迁移：只允许紧邻下一用户回合恢复，跨多轮必须重放。
- 回放保留最新指令；最新指令与系统超出预算时明确报错，不默默截断。
- 回放时转发可用历史图片；图片读取失败或超过数量限制明确反馈，不声称已完整传递。

### 状态一致性

- 模型切换失败阻止执行，不记录成已选成功。ACP 以真实模型选项确认，CLI 区分请求值与后端实际报告。
- 模型选择能力从真实会话选项判断，不将任意 select 误认作模型。
- 关键绑定和执行记录在 finish 前保存，消费者收到 finish 就退出也不跳过持久化。
- 开始执行前撤销旧绑定，取消、错误和部分工具执行后的上下文不会错误恢复。
- 终态幂等：错误不会被清理阶段覆盖成别的状态。
- 分叉继承历史证据并记录来源；会话关闭/删除使用所属 cwd。
- JSON 绑定首次加载去重，写失败后下一次写真正重试；避免原型键污染。

### 执行、计划与成果

- 工具调用按调用标识合并补丁，保留标题、类型、状态、输入、输出、文件位置与内容。重复同名工具独立显示。
- 计划保留状态与优先级；空计划更新可清空旧内容。回合结束未完成条目标记中断，不伪造完成。
- 结构化配置变化与可用命令更新保留；会话面板可调整后端真实提供的非模型 select 选项，保存到该会话。
- 执行记录持久化，重启时将遗留运行、工具和计划收敛为中断。仅在当前会话内展示。
- 工具详情按需读取，快照不携带原始大输出。
- 完成的文件修改事件可生成成果条目；检查文件存在、大小及工作区边界后标记“文件已验证”。
- 文本文件预览以纯文本显示，不执行 HTML/script。验证后文件发生变化时提示；工作区外路径、越界符号链接、大文件与二进制拒绝内联预览。
- 文件验证只代表文件确实存在，不代表任务正确、测试通过或修改符合需求。

### 生命周期与界面

- 每路由并发准入默认 2（可设 1–16）；同会话回合序列化。取消排队不会阻塞后续任务。
- 提前 Stop 与迭代器 return 均取消子进程工作，取消确认有界，CLI 支持静默 watchdog 及 TERM→KILL。
- 热配置变化清理旧传输、缓存与并发状态，不继续复用旧配置进程。
- 面板防旧响应覆盖、取消刷新、操作防重、超时、局部失败提示，并保留上次成功内容。
- 当前会话标签只标记当前对话；优先显示标题、项目与模型，不把原始会话标识作为主要 UI。
- 工具、计划、成果、实际模型、执行耗时和 Stop 独立呈现；保留轻量 reasoning fallback。
- 默认后台读取只读持久记录，不自动创建后端探测会话；打开会话管理/显式刷新才读取后端。
- 面板关闭且没有活动状态时停止轮询，隐藏页面不请求。详情区不强制跟随最新输出。
- 限制执行记录、工具数、详情长度、回放、流缓存和预览大小；脱敏常见凭证字段，服务只接受 loopback / 同源 / 自定义客户端头。

## 新配置

- agents.<route>.maxConcurrentTurns：默认 2，范围 1–16。
- agents.<route>.cancelTimeoutMs：默认 2000，取消确认期限。
- stateDirectory：可选，指定 profile 私有状态根目录。宿主没有 profileContext 且未注入 DSH_PROFILE 时应显式设置，避免多 profile 共享 fallback 状态。
- CLI jsonl 可选映射：toolId、toolStatus、toolKind、toolInput、toolOutput、model。未报告的实际模型显示“后端未确认”。

stateDirectory 下写入 agent-providers/sessions.json 和 agent-providers/activity.json。默认 40 回合、每回合 80 工具、40 成果、80 计划步骤；原始详情有界，仅按需返回。预览上限 256 KiB。

## 验证与复现

在工作副本运行 npm install，然后 npm test。

- npm run test:improvements：恢复、交接、模型拒绝、finish 提交、工具补丁、计划、重启、文件边界、取消和配置回归。
- npm run test:ui：真实 React DOM 组件测试，包括旧响应、防重、刷新失败和纯文本预览。
- npm run probe:host：需要 DSH_TEST_BIN 指向兼容 DSH 的 lib/bin.js；使用当前 Node 启动隔离真实宿主，驱动合成 ACP 子进程，不消耗模型调用，不接触 ~/.dsh。
- npm run probe:ui：需要 UI_VENDOR_DIR 指向单独安装 react@18.3.1/react-dom@18.3.1 的测试目录；只为浏览器 UI 验收，运行时仍使用宿主 React。页面所有样例均明确标注。

## 验收边界及仍需宿主协同

1. 已运行真实兼容 DSH headless 的插件加载、ACP 回合、块组装、usage 和持久状态烟测；后端是合成 ACP，而非收费模型。真实 React 组件已做 DOM 回归和浏览器交互验收。
2. 未修改或完整验收用户现有 DSH web profile。当地全局 DSH 低于项目已有最低版本，测试采用隔离兼容宿主，不自动升级用户安装。
3. 未用真实 Claude/OpenCode/TRAE 进行付费推理与生产会话迁移。本轮不把这些效果声称为已验证。
4. 原生聊天内卡片、结构化提问的通用返答通道、方案批准后继续执行、Git worktree/检查点回滚、跨设备订阅恢复仍需宿主和后端真实能力配合。未通过模拟工具调用、放宽权限或解析文本“完成”来伪造这些功能。
5. CLI 没有 DSH 原生授权返答通道，继续遵从后端自己的权限配置；本轮没有放宽 Agent 权限。
6. 文件 diff 来自后端明确提供的 diff 内容时可在详情查看，本轮不擅自运行 Git 修改、回滚、commit 或 push。
7. 目前只有有限快照与按需轮询，不宣称提供事件日志完全重建、SSE/WebSocket 断线续传或完整日志归档。
